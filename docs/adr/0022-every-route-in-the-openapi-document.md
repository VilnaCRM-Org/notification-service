# 0022. Every route in the OpenAPI document

Planning decisions: the maintainer decision of 2026-11-17 recorded in `specs/8-graphql-subscriptions-over-sse/prd.md`, specified by its FR-26 to FR-29 and bounded by NFR-13, NFR-16, NFR-17 and NFR-20, and the maintainer decision M5 of 2026-11-21 recorded there; the design is the section "OpenAPI Document of Every Route" of `specs/8-graphql-subscriptions-over-sse/architecture.md`. Amends [ADR 0006](0006-health-and-liveness.md), [ADR 0007](0007-api-contracts.md) and [ADR 0021](0021-graphql-subscriptions-over-server-sent-events.md).

## Context

The OpenAPI document listed three operations, the catalog `GET /api/event-types`, the node status `GET /api/events/status` and the readiness probe `GET /api/health`, while the service served eight more routes: the two streaming routes `GET /api/events/stream` and `GET /api/events/ws`, both forms of the GraphQL endpoint `/api/graphql`, the liveness probe `GET /ping` and the three documentation routes. [ADR 0006](0006-health-and-liveness.md) registered `/ping` "outside `/api` and outside the OpenAPI router", [ADR 0007](0007-api-contracts.md) described only the REST router, and the event-stream bundle kept the streaming routes out because a WebSocket and a response that never ends seemed beyond OpenAPI and its contract tests. A client therefore found half of the service on the Swagger page and the other half only in prose, and no test noticed a route served without an entry. Issue #8 asks for every route on the Swagger page, fully documented, and for a test that fails when a route is served without an entry.

## Decision

Each point below records one decision and its reason.

**1. Scope.** Every route the service serves is an operation of the document and of the Swagger page at `/api/docs`, the liveness probe and the three documentation routes included (maintainer decision of 2026-11-17): eleven operations, tagged `EventStream`, `GraphQL`, `HealthCheck` and `Documentation`. A test that fails for any route served without an entry needs no exception if no route is left out. This record amends ADR 0006, whose `/ping` is now an operation of the document, still outside `/api` and still touching no dependency, and ADR 0007, whose document now covers every router; it supersedes the choice of the event-stream bundle to keep the streaming routes out. Neither amended record is rewritten; the [decision record index](README.md) marks both "(amended by 0022)", as it marks ADR 0021, which point 6 amends. `API_VERSION` became `2.1.0`, the minor bump for added operations, and nothing was removed, so the breaking-change gate stays green without the label `approved-breaking-change`.

**2. One registration.** Every route is registered through `OpenApiRouter::routes(routes!(..))`, which takes the path and the method from the handler's `#[utoipa::path]` annotation and adds the route to the axum router and the operation to the document in one call, so a route cannot be served without its entry, nor documented without being served. Three routers carry the routes, because their handlers take three different states: `api_router()` the REST routes of the contexts (`AppState`), `graphql_router()` the GraphQL path (`ApiSchema`) and `operational_router()` the liveness and documentation routes (no state). `assemble` splits each router from its document, applies its state and merges the axum routers; `document()` merges their documents. The GraphQL path has one annotated GET handler, which serves the explorer in `dev` from a flag that the composition root puts in the schema data, so the routes and the document do not depend on `APP_ENV`. The asset route moved from `/api/docs/{*file}` to `/api/docs/{file}`, one path segment, because `routes!` writes the annotated path verbatim into both the router and the document and a catch-all is not an OpenAPI path template; every file of the embedded Swagger UI is one segment deep, and a deeper path now gets the router's 404 problem.

**3. Streaming operations.** A `text/event-stream` answer is described by the schema of one event (`SseFrame` with `event`, `id` and `data`, `GraphQLEvent` with `event` `next` or `complete`, an optional `id` and `data`), the convention of OpenAPI 3.2 that Schemathesis reads; each `data` is a string whose `contentMediaType` is `application/json` and whose `contentSchema` is the event object or the execution result, and the bare `data:` of `complete` is admitted. The WebSocket route answers `101 Switching Protocols`, documented with the response headers `Upgrade`, `Connection` and `Sec-WebSocket-Accept` and a description of the server's frames and the client's commands, because OpenAPI 3.1 has no WebSocket object; the handshake headers are required header parameters whose schemas admit exactly what the upgrade accepts. Every parameter schema admits the values a route accepts and refuses those it refuses, so generated requests meet the answers the route gives; a fault a schema cannot express, a repeated type name counting once, is named in the description. The JSON-encoded `variables` and `extensions` of the GraphQL GET form are strings described by `contentMediaType` and an object `contentSchema`. The description types (`SseFrame`, `GraphQLRequest`, `GraphQLResponse`, `GraphQLEvent`) are used by the annotations only, so the bytes on the wire do not change.

**4. The GET rule of the negotiation.** On a GET of `/api/graphql` a wildcard range (`*/*`, `text/*`) admits the event stream, because a GET has no JSON representation and RFC 9110 (section 12.5.1) lets a wildcard accept any type; a GET without an `Accept` field keeps its 405 problem with `Allow: POST`, or the explorer in `dev`, so every caller of today keeps its answer. A schema-valid GET from a generic client, which sends `Accept: */*`, is therefore answered with an event stream instead of a 405 that the contract tests would count as a refused valid request. In `dev`, curl's default `*/*` now gets the event stream instead of the explorer, and a GET without `query` the 400 problem; a browser navigation ranks `text/html` higher and keeps the explorer.

**5. Completeness tests.** Three tests of the composition root hold the document and the router together. A source oracle reads the non-test sources of `crates/service/src` and of the application crates whose routers `api_router()` nests and fails on any `.route(`, `.route_service(` or `.nest_service(` call, naming the file and the line, so no route can be registered outside the document. The document must list exactly the eleven operations, with their paths, methods, operation ids and tags, each with a summary, a description, its parameters with schemas and examples, every status code with media type, schema and example, and a `default` problem answer. Every operation must be served: a request for each path and method through the router of each `APP_ENV` reaches its handler, never the router's 404 fallback or its 405 answer. The document that `GET /api/docs/openapi.json` serves must equal the committed snapshot byte for byte, and an end-to-end scenario finds the eleven operations in it.

**6. Schemathesis.** `make schemathesis-validate` runs with its protected flags (`--checks all --phases=examples,coverage`) against the production image of the load-test stack. A failure is fixed at its root, in the document or in the code; an operation is excluded only as a maintainer's decision after an escalation that names the failing check, the reason and the exact exclusion, never by a story. The one such decision excludes `GET /api/events/ws` (commit `71aab46`, approved on 2026-11-17): Schemathesis reports the valid handshake's `101` as a failure, and no answer of the service can change that. The operation stays documented on the Swagger page, and the other ten operations are tested, the event streams included, which Schemathesis reads until 20 events or 10 s. Every string member of a request body carries a `maxLength` that the service enforces with the 422 problem: Schemathesis sends 65 537 characters to a body string without one and expects it accepted, so the size limit alone would refuse a schema-valid body with the 413. The bounds of the GraphQL `query` (4 096 characters) and `operationName` (128), on both forms, are chosen so that the default `HTTP_MAX_BODY_BYTES` holds both at their bound in their longest encoding, twelve bytes per character; the maintainer approved this new refusal of today's longer documents as decision M5 of 2026-11-21. This bound amends [ADR 0021](0021-graphql-subscriptions-over-server-sent-events.md) point 5, its sentence on the answers before the stream and its sentence on the limits of P18, and point 2 on the request formats: on both transports and both forms, a `query` over 4 096 or an `operationName` over 128 characters, counted in Unicode code points, is refused with the 422 length problem, type `/problems/validation-failed` with one `length` violation per member over its bound and never its value, after every other transport problem of its form (on POST the 415, 413, 400 and 422 problems of today, on GET the 414, 400 and 422 problems). ADR 0021 keeps its sentences: its points 2 and 5 end with a note that names this point, and the index marks it "(amended by 0022)".

## Consequences

The Swagger page shows every route the service serves, with the examples of the load-test type, and a client generator sees the whole API. A new route needs its annotation and its `routes!` registration; without them the route oracle or the exact operation set fails, and an annotation without a route fails the served-operation test. A change to the document needs `make generate-openapi-spec`, because the served document is compared with the snapshot in the unit tests as well as by `make validate-contract-snapshots`.

The streaming operations are in the contract gates: Spectral lints them, oasdiff compares them and Schemathesis exercises them, except the WebSocket route, which Spectral's rule `operation-success-response` exempts for its `101` alone (the approved override `a374895` in `.spectral.yaml`) and which Schemathesis skips by the approved `71aab46`. The protected Bats tests of the OpenAPI gates keep their meaning without a change: G17 removes the first operation description, now that of `GET /api/docs`, G19 the required `title` of `Problem`, and G21 plants an undocumented path. The liveness and documentation routes are template files that this record changes, so `.templatesyncignore` lists `crates/service/src/http/ping.rs`, `crates/service/src/http/docs.rs` and their test directories.

Alternatives rejected: keeping `/ping` and the documentation routes out (the completeness test would need exceptions); one router with one state (the GraphQL handlers and the router tests rely on `State<ApiSchema>`, and `AppState` would gain a schema field); documenting a route by hand next to a plain `.route(..)` (the two could drift); an AsyncAPI document for the frames (a second contract for two routes); a catch-all asset path (not an OpenAPI path template); relaxing a Schemathesis check or excluding more operations (each failure is fixed at its root or escalated).
